# Plugin bounty program

> **Status: charter.** Reward amounts below are **PROPOSED** until the
> maintainers confirm funding for a milestone; funded items will be listed in
> the "Open bounties" table with a concrete amount and issue link. Nothing on
> this page is a payout promise.

The bounty program funds community-built plugins for forge — the fastest way
to grow the ecosystem while the core stays small.

## What qualifies

Work is bounty-eligible when it ships as a **plugin** (a directory with a
`forge.plugin.json` manifest + hook handlers) or as a clearly scoped
contribution to the plugin kernel, *not* as a fork of the core loop.
Examples: new tool surface behind the hook engine, provider glue for the
adapter layer, marketplace tooling, TUI panel contributions through the
plugin API.

Bundled starters live in [marketplace/plugins](../marketplace/plugins) — read
them first; they are the working reference for manifests, hook contracts and
docs generation. The generated reference is at
[`/plugins/` on the docs site](https://inbesat.github.io/Munchkin-CLI/plugins/).

## Proposed tiers (awaiting funding confirmation)

| Tier | Scope | Proposed reward |
| --- | --- | --- |
| T1 — Utility | Single-hook plugin with docs + tests (e.g. a guard hook, a formatter integration) | $50–100 |
| T2 — Capability | New tool surface or provider glue usable from config, end-to-end tested | $150–300 |
| T3 — Kernel | Loader/hook-engine/marketplace improvement accepted upstream | $300–500 |

Rewards are paid after **merge + release that ships the work**. One bounty
per merged change; co-authored work splits the reward.

## How to claim

1. Pick a bounty from the "Open bounties" table (or propose one via the
   feature-request template — check the **Bounty interest** box).
2. Comment `claiming` on the bounty issue; we assign it to you for 30 days.
3. Fork, implement against the plugin guide
   ([docs site](https://inbesat.github.io/Munchkin-CLI/docs/guide/plugins.html)),
   include tests and a README for the plugin.
4. Open a PR linking the bounty issue. Reviewers verify: manifest validity
   (kernel loader must accept it), tests green, docs generated by
   `scripts/generate-plugin-docs.ts`, no secrets, no telemetry added by the
   plugin without an explicit opt-in switch.
5. On merge + release, fill the payout details via the private channel the
   maintainers provide **at funding time** (never post payment details in the
   issue).

## Quality bar (same rules as core)

- Runs on Windows, macOS and Linux (or gracefully reports its platform limits).
- No new runtime dependencies in core; plugin deps stay inside the plugin dir.
- Isolation contract: a failing plugin must degrade its own features only.
- Everything measurable: if you claim speed/accuracy gains, include the test
  that proves it.
